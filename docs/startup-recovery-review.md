# 启动恢复与托盘更新复核

## 已确认的根因

现场日志中的 `TaskCanceledException` 包含 `TimeoutException: ConnectTimeout`，调用链为
`HttpRemoteFetcher → RuleArtifactStore → PrepareRuntimeAsync`。这是 TUN 启动前的 SRS 下载超时，
不是用户取消 TUN。旧的组合根创建普通 `HttpClient` 并关闭系统代理，却没有配置 SOCKS 连接器，
因此下载依赖 Windows 默认网络，所选默认端口未参与。

同时，发布目录中的 GuardTray 已是新提交，Program Files 内首次安装的副本仍是旧提交。
旧副本继续提供旧菜单。文件名相同，替换发布目录不会自动替换已安装副本；本次补上同步。

## 调用链与修正

| 范围 | 处理与验证 |
| --- | --- |
| 所有远程启动资源 | 规则目录、SRS、release 元数据、ZIP 统一经 DefaultProxyDownloadTransport；只使用所选默认 SOCKS5 端口，不做系统直连回退。 |
| 端口变更 | 每个传输固定一个端口；待应用配置在独立异步作用域中使用新端口，并发目录更新保持已保存端口。没有跨请求释放 HttpClient。 |
| 重定向 | SOCKS ConnectCallback 对每个新 TCP 连接生效；模拟 SOCKS 服务验证重定向后的第二个域名也经过相同端口。 |
| 时间限制 | 连接 8 秒；普通传输 30 秒，包含正文；内核 ZIP 正文总预算 5 分钟。用户取消透传，连接/正文/CLI 超时显示独立原因。 |
| 内核缓存 | 先校验 current，必要时再校验 last-good；验证摘要、实际版本和配置。有效缓存不依赖 release API；损坏缓存不被使用。 |
| 规则缓存 | 校验固定 commit/blob SHA；目录缓存缺失或损坏时经默认代理自动恢复目录；不删除用户所选规则来绕过失败。未选择 SRS 时不请求规则资源。 |
| 启动状态机 | 取消源由创建它的操作释放。过期操作不能把新操作的状态改回 Preparing/Failed；在修改内核之前再次检查取消。 |
| 当前状态与历史 | 新一轮准备显示当前资源进度。旧占用、旧超时保留在历史中，不作为新一轮的当前原因。 |
| 守护边界 | 心跳仍只判断主程序与 TUN。联网检查仍由主程序负责；没有把下载/统计结果混入守护心跳。 |
| 托盘副本 | 比较完整 payload 字节摘要；先暂存并校验，再按完整路径与创建时间处理旧托盘实例，替换原安装目录。服务、自启选择、手动停止标记均保持。失败尝试回滚旧目录。 |
| 菜单定位 | 使用通知图标所在显示器的物理坐标、DPI 与工作区；限制可见卡片，透明阴影不把卡片顶离图标。初始鼠标打开不显示键盘焦点框；键盘操作仍有焦点样式。 |

`UseProxy = false` 不是可以全文替换的标志：剩余两处分别是**显式 SOCKS 连接器**（禁用 Windows
全局代理、所有 TCP 经 SOCKS）和 **127.0.0.1 的 sing-box 管理 API**（避免代理回环）。普通系统
直连下载客户端已移除。

## 组合 mock

启动矩阵是以下状态的完整笛卡尔积，共 **3,456 组**：

| 维度 | 状态数 | 取值 |
| --- | ---: | --- |
| TUN 占用 | 2 | 无冲突 / 被占用 |
| 两张网卡 | 4 | 分别在线或离线 |
| 默认代理 | 6 | 正常 / 未配置 / 拒绝连接 / SOCKS 协议错误 / 超时 / HTTP 失败 |
| SRS 选择与缓存 | 4 | 已校验 / 缺失 / 损坏 / 没有选择规则 |
| 内核缓存 | 3 | 已校验 / 缺失 / 损坏 |
| 恢复时端口 | 2 | 保持原端口 / 切换默认端口 |
| 恢复时取消 | 3 | 不取消 / 准备前取消 / 应用前取消 |

每组使用实际规则缓存、内核缓存、配置编译器和生命周期协调器；HTTP、CLI、TUN 进程为 mock。
检查启动允许条件、离线出口的 reject 规则、保护判定、选定端口、失败后的恢复、取消不替换内核、
相同配置不重启，以及真实接管失败仍撤销就绪。目录缓存另有 12 组有效/缺失/损坏 × 网络 × 取消组合。
还覆盖正文超时、重定向、并发端口作用域、过期操作、托盘更新阶段失败和多 DPI 菜单几何。独立守护小托盘的停止/运行 × 100%/150%/200% 六个场景直接复用生产菜单工厂，验证其自己的图标、按钮状态和点击动作。

临时文件只在测试目录内；没有使用真实代理端口、启动真实 TUN、改变真实服务或网卡。
NativeAOT 编译、包生成和 mock smoke 不会触发生产初始化。测试覆盖明确枚举的状态与边界，
不把 mock 结果表述为已在用户机器上进行真实网络切换验证。
