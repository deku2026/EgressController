# Subscription groups, latency and live routing

The typed policy/DSL is the shared source for onboarding, application/rule pickers, group cards, compilation and runtime updates. Applications never acquire a node identity or a new executable inventory from a group edit.

## Import and retained groups

Clash import preserves declared membership/order, provider membership, nested groups, URL, interval, tolerance and icon metadata. New `select` groups initialize from a valid `default-selected`, otherwise their first declared member. A node-only subscription receives a stable default `url-test` group. Existing unresolved saved choices are not guessed or reset.

`retained: false` removes a group from normal workspace/picker choices, not from the graph. Default groups and groups referenced by saved application/rule routes cannot be unchecked in the UI. Nested dependencies remain usable. Refresh preserves retention, manual choices and explicit mode overrides; an explicitly added DIRECT option also survives refresh. Removed subscription members remain unresolved metadata; unselected unavailable members are hidden by default. A missing current selection remains visible for repair and is never silently replaced.

Each group can explicitly select DIRECT, mapped to the configured non-home interface. REJECT remains a blocked choice when declared. There is no automatic direct substitute for failed proxy probes. Neither builtin can be a node's dialer chain. Unsupported protocols and dynamic group filters/options retain actionable diagnostics rather than being silently approximated.

The native card list uses shared Inter/CJK typography, semantic tokens and adaptive product artwork. Known product names/icon filenames map to bundled icons; unknown groups use a consistent fallback. Importing an arbitrary icon URL does not perform a hidden UI network fetch. Onboarding chooses retained/default groups without a separate download-node page.

## Observations and automatic selection

Explicit group tests traverse that group's leaves with its configured URL. “全部测速” tests retained groups. The default endpoint is `https://www.gstatic.com/generate_204`. Observations carry actual timestamps and URL identity; missing, stale and failed results never become 0 ms. Tests use at most six unprivileged Xray observatory processes, with an eight-second per-process deadline, each containing only the target and required dialer dependencies. Publication is coalesced on the UI dispatcher; probing has its own cancellation state and never disables workspace navigation. These processes have no TUN or listener, bound to non-home. This is latency measurement, not a throughput/traffic estimate.

A separate policy timer checks the already-applied automatic groups at their configured intervals. `url-test` uses fresh successful observations and tolerance; `fallback` uses declared order. Explicit measurements immediately reevaluate applied automatic selections too; subscription import/preview hydration never auto-applies a configuration. Manual member selection saves an explicit `select` override. Background updates operate on the applied snapshot, cannot overwrite pending edits, and yield to user operations through operation-owned cancellation. Probe failure retains current routes and does not produce a guardian/network-protection failure. Status/telemetry failures are not selection inputs.

## Automatic rule-download exit

Connection establishes the authorized TUN before group probes or remote rule preparation. Rules first attempt a cache-only read with integrity/format validation. If resources are missing, probe non-DIRECT leaves of the default group with its test URL, prefer its resolved node when successful, otherwise choose the fastest successful leaf. No available proxy produces `resources.no-proxy`; there is no direct/system-proxy fallback. This works even when normal default-group traffic explicitly selects DIRECT.

The selected download node is transient compile input, not a second saved group choice. Downloads retain the scoped loopback SOCKS port and DefaultProxyDownloadTransport. Subscription/provider acquisition remains the separate direct HTTPS/non-home path. Cached resources need neither a download probe nor an available download node.

## No-restart routing boundary

The compiler loads all valid, resolvable subscription node outbounds so normal group switches only change routing. The helper independently validates the whole candidate generation and compares all non-routing runtime fields, physical service identities and routing domain strategy. Only an unchanged listener/TUN/DNS/outbound configuration with confirmed existing takeover is eligible for a live route update.

The trusted helper alone injects RoutingService into `core.runtime.json`. Its socket is inside the root-owned private directory; user-supplied `api` and runtime-file overrides remain rejected. The pinned Xray CLI runs `api adrules --server=unix:///…/routing.sock --append=false` with helper-generated routing JSON and verified DAT assets in a stable root-private asset directory. Both core startup and the CLI use that directory. DAT filenames are content-addressed, and candidate/rollback references are rewritten to those immutable names; callers cannot submit helper runtime files. This replaces the complete table atomically while keeping core, TUN, DNS and existing connections. Bootstrap completion uses this same path when its outbounds are unchanged.

If the RPC fails or cancellation makes its outcome uncertain, restore the complete previous table with independent bounded cancellation. Report `routing.update` only after restoration succeeds; failed restoration is `recovery.failed` and triggers existing recovery. Concrete runtime changes (node transports/dialer chains, interfaces, DNS or listeners) still require a logged reconfiguration. This feature does not promise that arbitrary configuration changes are restart-free.

Per-record telemetry generation preserves existing observed labels through a hot update; new records use the new generation. Telemetry remains observational and never controls the core. Guardian continues to use authenticated GUI identity/liveness and actual TUN takeover only.

## Startup diagnosis and verification

The reported 2026-11-01 logs showed successful TUN establishment and rule preparation followed by a second core start at full routing application. Route-only bootstrap completion now avoids that second start. A follow-up at 07:31/07:32 established TUN, validated the full configuration, then rejected the routing RPC while successfully restoring the bootstrap table. The coordinator subsequently stopped bootstrap and restored the pre-connection network, making the former “TUN remains running” message incorrect.

The pinned CLI builds lazy DAT references: its own candidate asset directory is not transferred to the running process. Xray resolves those references in its startup asset directory, which previously belonged to the asset-free bootstrap generation. `RuntimeAssetPublication` now publishes verified DAT files by SHA-256 into the helper's stable private directory before either startup or hot update. Old immutable files remain usable for rollback. `Verify-XrayRoutingRpc.py` executes only the pinned **API client** against a synthetic Unix HTTP/2/gRPC peer: it checks lazy filenames, reproduces a mismatched server directory and verifies new/old immutable filenames against one unchanged directory. It never starts an Xray server or TUN.

API errors retain only a fixed classification (missing/load-failed asset, timeout, unavailable, permission, rejected) and exit code. Raw core output, paths and credentials are not logged. The current error describes rule restoration without promising TUN remains up after a surrounding bootstrap cleanup. These changes have isolated regression evidence; no live-network success is claimed.

Startup diagnostics now classify bounded fatal output into fixed port, permission, TUN or configuration codes, and record the exit code before recovery. They never forward raw per-connection errors or credentials. Main/helper/native payload identity is checked so a new UI cannot silently keep an old helper implementation. Diagnostic failures remain outside protection decisions.

Validation uses injected resources/runtime, synthetic subscriptions, pure native ABI checks, actual headless pointer/keyboard input, normal/compact rendered states, and NativeAOT GUI/helper mock smoke. No real TUN, helper installation, system DNS/routes or protected targets are used. Cases cover DIRECT/download separation, refresh retention, atomic route replacement and rollback/cancellation, applied-versus-pending automatic edits, observation generation, and inventory preservation.

## Reset and fresh onboarding

Settings and connection-error surfaces open a shared native confirmation overlay. Cancel/Escape leaves the document and runtime intact; initial focus is on cancellation, keyboard traversal stays inside the dialog, and underlying editing is disabled. Explicit confirmation serializes with apply and cancels/awaits automatic group maintenance. It attempts network restoration independently of the local reset, backs up the edited typed policy as `configuration/policy.before-reset.draft`, prepares an empty recovery draft, and atomically replaces `policy.draft`. Files use private permissions, checksums, fsync and directory synchronization. The reset backup survives ordinary draft rotation. It can be recovered manually by taking its YAML payload (after the two envelope lines) into the DSL editor; it is never automatically applied.

The UI clears subscription inputs, selected interfaces/groups, applications, rule selections, probes, applied-group snapshots, pending filters and connection-attempt state only after successful persistence. The first step requires two distinct interface choices. No discovery, service installation, process termination, cache deletion or automatic reconnection is performed by reset. A failed stop or unavailable helper does not veto local reset: a typed result preserves the unresolved recovery warning and the existing privileged recovery journal. Explicit repair verifies/reinstalls the current helper identity through administrator authorization, then stops/restores without applying a generation or starting TUN. A failed backup/reset preserves the UI draft and refreshes runtime state because the stop may already have succeeded. Logs, validated resource caches and usage history remain outside the reset scope.

Coverage includes stop/storage/cancellation sequencing, private durable backup and corruption recovery, cancel/confirm and failure UI states, blank setup followed by re-import, and normal/compact renders with hover/pressed/focus/disabled states. Fixed executable inventories change only upon explicit confirmed reset, not route or group edits; guardian/network separation remains unchanged.
