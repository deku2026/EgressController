# EgressController

EgressController 是一个 Windows x64 双网卡分流与断网进程保护工具，主要服务于 AI 应用和浏览器。
如果你同时有一条家宽（或 eSIM、手机共享）和一条非家宽网络，它可以把所选应用固定到家宽出口，
把本地代理核心固定到非家宽出口，再按应用、域名或规则集选择直连与本地 SOCKS5 代理。

它还会持续检查 TUN 接管、两张网卡和网络连通性：网卡掉线或任一出口的联网检测连续三次失败时，
自动关闭你勾选的应用，并在故障期间持续关闭重新启动的实例。DNS 配置固定为 Cloudflare DoH，
不检测 DoH 健康状态，也不将 DoH 响应作为关闭程序的条件。
网络恢复并检测通过后解除保护，应用由你手动重新打开。网卡角色名称只是配置标签，不会自动判断线路是否属于家宽。

首次打开主程序还会安装并启动独立的 NativeAOT 守护服务与 Avalonia 小托盘，默认开启开机启动。
主程序未运行、通信失联或 TUN 未接管时，服务持续终止最近勾选的应用。它与主程序的联网检测是两套独立条件，
小托盘的红点只反映主程序/TUN 守护状态。退出主程序后服务仍工作；可以在主程序或小托盘中明确停止、禁用或卸载。

sing-box 负责 TUN、DNS 与实际流量转发；C# / Avalonia 提供桌面界面、应用扫描、配置、内核管理、
网络检测和进程保护。项目不提供代理节点或订阅；需要代理时，应另行准备本地 SOCKS5 服务。

## 开始使用

1. 在 Windows x64 上完整解压发布包，保留 `guard-service`、`guard-tray` 子目录，以管理员权限运行 `EgressController.App.exe`。
2. 选择两张不同的实际网卡：`ESIM-家宽` 用于默认直连与 DNS，`Proxy-代理` 用于非家宽出口。
3. 需要代理时添加已有的本地 SOCKS5 端口，关闭上游代理自身的 TUN；也可以只使用网卡直连。
4. 勾选要分流和保护的应用，按需设置应用、域名或 SRS 的出口。
5. 等待 TUN 与网络检测通过，再打开所选应用；在“网络与内核”查看检测结果与关闭记录。
6. 在“独立守护”查看已创建的服务名称、状态、PID、账号、路径、自启设置及守护终止记录。

## 独立守护与小托盘

| 组件 | 职责 |
| --- | --- |
| 主程序 | 管理配置和 TUN，执行原有网卡与联网检测保护，发送独立的 TUN 心跳 |
| NativeAOT Windows 服务 | 从 SQLite 恢复最近名单，核验主程序身份、心跳与 TUN；条件不满足时持续终止所选进程 |
| NativeAOT Avalonia 小托盘 | 显示红点、原因、守护记录，打开主程序，管理守护服务 |

异步命名管道按已登记的完整主程序路径、用户 SID、PID 与创建时间确认通信身份，不按进程名判断。
主程序每秒发送一次 TUN 状态；服务每秒检查，通信断开时立即唤醒检查，超过 3 秒未更新也进入保护。
服务独立核验受管理核心进程、TUN 接口身份、地址及接管路由。只有当前会话、当前名单版本、主程序在线且 TUN 接管正常，
才停止**守护服务自身**的终止；网络失败时主程序仍可以根据原有规则终止应用。这里的 1 秒/3 秒与联网检测的 30 秒/5 秒无关。

保护名单保存完整 EXE 路径、勾选目录及递归范围。服务同时匹配目录内新增或更新的 EXE、所有运行实例和已追踪子孙进程，
主程序未运行时无需重新扫描全部磁盘。服务以 LocalSystem 运行，但只处理登记用户的进程；每次终止验证 PID 与创建时间，
排除控制器、守护组件、sing-box 和已识别的上游代理。服务重启后也保留已追踪、父进程已退出的子进程身份。
已追踪进程暂时无法读取时保留身份并报告终止失败，不把“读取失败”当成“已经退出”，也不按旧 PID 盲杀；
只有确认退出或确认 PID 已被其他创建时间的进程复用后，才移除该身份。

- 红点：主程序离线、TUN 未接管或状态无法确认；窗口中显示具体原因。正常：主程序在线且 TUN 已接管。
- 灰色：用户明确停止/卸载，当前没有独立守护保护。停止失败或通信失败仍显示错误，不伪装成正常。
- “停止服务”及“强制停止”：记录停止意图，本次 Windows 启动期间不会因重开主程序或服务故障恢复而自动拉起；仍可手动启动。下次开机遵循自启设置。
- “开机自动启动”：默认勾选，同时控制服务开机启动和小托盘登录启动。仅取消勾选不会停止已经运行的服务；可用“停止并关闭自启”同时完成。
- “卸载服务”：停止、移除服务及托盘登录启动项，保留名单和记录；不会在下次打开主程序时自动重装。需要时显式“安装服务”。
- 关闭小托盘窗口会隐藏；“退出小托盘”只退出显示程序，服务继续运行。服务管理需要管理员权限，普通权限小托盘会通过 UAC 发起操作。
- 主程序计划退出或重启 TUN 前先让服务接管并确认终止结果；同步或终止失败则取消操作并显示错误。手动停用服务时，主程序仍执行自己的保护检查。
- 两套终止记录分别显示，均保留最近 24 小时、最多 200 条，提供清空按钮。清空不取消保护和身份追踪。

首次安装失败、发布组件缺失、配置或数据库损坏会显示错误，不以空名单/历史“就绪”替代。
主程序位置已登记；移动发布目录或更换守护二进制时，需要显式停止并卸载，再从新目录安装，避免静默替换正在保护的服务。
完整协议、持久化和故障边界见 [独立守护设计](docs/independent-guard.md)。

## 断网时如何保护

| 检查 | 频率 | 关闭所选应用的条件 |
| --- | --- | --- |
| 主程序在线与 TUN 接管（独立服务） | 每秒，断线立即唤醒；心跳超时 3 秒 | 主程序缺失/失联、未接管、核心退出、接管路由丢失或配置未生效 |
| 家宽和非家宽网卡 | 每秒 | 任一所选网卡掉线、消失或没有可用 IP |
| 家宽联网 | 每 30 秒一轮；失败间隔 5 秒复测两次 | 经家宽绑定出口访问联网探测地址连续三次失败或超时 |
| 非家宽代理联网 | 每 30 秒一轮；失败间隔 5 秒复测两次 | 经当前默认 SOCKS5 代理端口访问联网探测地址连续三次失败或超时 |

两个出口均使用 [Cloudflare 联网探测地址](https://cp.cloudflare.com/generate_204)：家宽通过绑定家宽的
直连出口访问，非家宽通过当前默认的本地 SOCKS5 代理访问，结果分别保存。非家宽探测验证
“本地代理端口 → 代理节点 → 网站”的访问过程，不要求非家宽网卡能够直接访问该网站。
TUN 启动后立即进行首轮检查；之后按轮次开始时间每 30 秒检查一轮，也可手动检测；复测未完成时不会重叠启动新一轮。
每个出口独立确认：首次失败 → 等待 5 秒 → 第二次检测 → 再失败则等待 5 秒 → 第三次检测。
任一次成功立即结束该出口的复测；只有连续三次失败才发布故障结论。每次最多等待 8 秒。

- 首次启动、实际切换 TUN 配置或受影响网卡恢复后，需要新的成功联网检测才能放行；网卡恢复后等待下一轮定时检测或手动检测。
  准备/下载/校验候选配置期间沿用当前生效配置与最新检测结论；候选失败不重置正常状态，也不覆盖期间检测出的新故障。
- 代理探测跟随已生效的默认端口，不固定为 `7890`。更换默认端口并应用配置后丢弃旧结果，重新首检；旧端口的迟到结果不能覆盖新端口状态。
- 没有配置任何代理端口时，纯直连模式只做家宽网站检测，界面明确显示代理检测未启用；仍检查两张网卡的连接与 IP，不虚构代理成功结果。
- 普通复检期间保留上次完成的结论：上次通过不因“检测中”关闭，上次失败继续关闭；前两次失败仅显示复测进度，不改变保护结论；第三次仍失败才更新保护条件，进程守护在下一轮检查时执行关闭。
- 取消的检测与旧配置的迟到结果不能覆盖有效状态。DNS 返回什么状态都不会作为联网健康结果。
- DNS 配置写死 Cloudflare，不进行 DoH 健康检测、备用选择或自动切换。联网检测失败不会修改 DNS 配置或重启 TUN；保护期间保留恢复通信。
- 关闭范围是全部勾选应用及其追踪到的子孙进程，不按应用当前选择的出口区别处理。未勾选应用不属于关闭范围。

如果保护记录中出现 `/proxies/.../delay` 的 HTTP 504，表示 sing-box 的 HTTPS 联网探测超过了
5 秒内部时限，并非 DoH 健康检测结果。单次失败会先触发复测，连续三次失败才按保护规则关闭程序；它只能说明指定出口本轮未能完成
对探测地址的访问，不能单凭这条记录判断是 DNS、连接、TLS 还是目标站点导致。

## 当前行为

- 启动后立即进入进程保护，再扫描应用、准备内核和规则、自动启动 TUN。每秒检查进程与启动状态，
  同一次启动未完成时不重复启动。界面和托盘不再提供停止 TUN 的入口。
- 应用需要管理员权限。sing-box 负责全流量 TUN 与分流，C# 负责配置、发现、健康检测和进程保护。
- 网卡固定为两个角色，实际网卡由用户从本机接口中任意选择两张不同的网卡：
  `ESIM-家宽` 是应用的默认直连出口，`Proxy-代理` 是所有本地代理核心的出口。
  两个角色都可更换或交换网卡，没有添加第三个角色的入口。支持有线、Wi-Fi、USB 共享、蜂窝；
  默认只列出在线且有 IP 的常见接口，“显示更多”可查看离线和虚拟接口。回环与自身 TUN 不可选。
  按 GUID 保存绑定；所选网卡掉线或消失仍保留选择，绝不自动换网卡。
- 多个 SOCKS5 端口及默认端口独立保留。每个端口自动识别监听 PID 和完整 EXE 路径，
  多个端口可以属于同一个核心进程；所有已识别核心统一通过绑定 `Proxy-代理` 的 direct 出口。
  该规则优先于应用、域名及默认端口，防止再次进入自己的 SOCKS 端口。
  代理网卡不可用时拒绝这些核心的流量，不使用控制器恢复通信的备用路径。
  界面显示端口对应的 PID、完整路径、网卡和识别失败原因；代理重启后重新识别并检测。
  端口身份未确认时拒绝送往该端口的流量，避免未知核心递归进入默认 SOCKS 端口。
- 勾选应用默认使用“默认直连 · ESIM-家宽”。应用、域名和 SRS 可选择任意一个角色直连，
  或选择默认/具体代理端口。更换角色网卡时，相应显式规则跟随角色一起更新，DNS 固定跟随直连角色，
  端口配置保持独立。没有 SOCKS5 端口的纯网卡配置也可以准备 TUN。
- 独立服务检查主程序与 TUN；主程序网络保护检查两张出口网卡、家宽及已配置默认代理的上次联网检测结果。
  启动确认包括本地 API、核心进程、TUN 接口地址及 IPv4/IPv6 默认接管路由，不能只凭核心进程存活报告成功。
  启动前检查其他活动 TUN/VPN（接口类型及 Wintun、WireGuard、Mihomo/Clash 等标识），冲突时显示接口名称并保持进程保护。
  接管后持续核验接口 GUID，以及公网路由的前缀和路由/接口总跃点数：其他接口的更具体公网路由（包括 /1），
  或优先级相同/更高的默认路由，会被保守判为冲突。未知接口拥有公网路由也不能确认接管。
  离线虚拟接口和普通虚拟以太网的局域网路由不因此报错；本机地址的主机路由不视为公网绕行。
  本检查不覆盖所有第三方驱动或应用自行绑定接口的行为，不等同于内核防火墙。
- DNS 固定通过 `ESIM-家宽` 使用 Cloudflare。联网检测与 DNS 配置独立：sing-box 分别通过绑定家宽的
  `dns-direct` 和当前默认代理的 `upstream-<端口>` 访问 `https://cp.cloudflare.com/generate_204`。
  例如默认端口为 `1080` 时检测 `upstream-1080`，实际连接 `127.0.0.1:1080` 的 SOCKS5 服务；
  `upstream-` 只是内部标签，不限制代理软件品牌。`proxy-direct` 继续用于把代理核心的对外连接
  固定到非家宽网卡，不再直接承担网站探测。代理检测失败不回退到直连、其他端口或家宽出口。
  该检查针对当前默认代理；为特定应用或域名指定的其他代理端口不在本次网站健康检测范围内。
- 出口网卡掉线时，配置保留原接口/地址绑定，进程守护依据实时网卡状态关闭所选应用。
  不自动换到另一张网卡；恢复后的实际地址/名称变化、代理路径/规则变化会重新应用配置。
- 配置变更先生成并校验新配置，再终止所选应用并重启核心。终止失败则取消变更并显示原因；
  恢复后不会自动启动应用，只有接管和网络检测通过后才解除保护。
  候选准备失败保持旧配置；相同配置不重启，扫描未勾选应用也不打断就绪状态。
  首次启动或回滚未通过接管检查时停止失败核心；无法确认停止则显示清理错误，继续保护。
- 应用分流始终使用完整路径的大小写不敏感规则，不扩大为同名 EXE。勾选目录直接生成带目录边界的递归规则，
  新增 EXE 无需等待重新扫描即可匹配该目录出口；已有目录覆盖的相同出口 EXE 不额外改变配置。
  保护和分流同时保留所选路径与解析出的 junction/符号链接真实路径，避免两者使用不同身份。
- 保护按完整 EXE 路径、勾选目录及子孙进程匹配所有运行实例；不区分网卡或端口。
  新发现且不在现有目录/路径规则内的子进程，先终止并显示“分流规则尚未生效”，
  再把完整路径加入所属应用的出口配置；成功应用后可手动重开。代理核心的高优先级防循环规则保持优先。
  终止前验证 PID 与创建时间，避免 PID 复用误判。TUN 与网络检测均正常后停止终止，应用由用户重新打开。
  这是进程保护，不是系统防火墙：终止前可能已有请求，未勾选应用不属于终止范围。
- “进程保护”页显示原因，以及最近 24 小时内最多 200 条终止结果、应用名、路径、PID 和时间。
  记录自动清理，提供“清空记录”按钮；清空只影响显示，保留进程追踪和失败重试。
  权限不足、身份无法确认、终止尚未完成都明确报告；同一失败会重试但不每秒刷屏。
- 控制器自己的下载使用独立的直接 HTTP 客户端，不依赖本地 SOCKS5 启动成功；TUN 配置优先放行
  控制器和核心的恢复通信。默认端口身份未知时，未匹配流量也会拒绝。
  下载时限覆盖响应头和正文，流式读取即检查大小上限；正文卡住或超限会报错并允许后续重试。
  勾选范围包含控制器、核心或上游代理时报告冲突，不终止这些恢复依赖。
- 应用发现仍使用 Windows Store/MSIX、卸载注册表、App Paths 和 Program Files。已选择但暂未发现
  的项目保留在列表，仍可取消选择；缓存已扫描的 EXE 路径，供下次启动扫描完成前进行保护。
- 业务规则优先级仍为应用、自定义域名、SRS、默认端口；没有端口时，未匹配流量使用默认网卡出口。
  指定网卡启动时不可用则对应规则拒绝，运行中离线则绑定出口连接失败，指定端口离线时连接失败，不回退到其他业务出口。
- 关闭主程序窗口继续在托盘运行；“退出主程序（独立守护继续运行）”清理所管理 TUN，服务继续保护最近名单。
  主程序崩溃或没有启动时也由独立服务保护。服务被用户停止/卸载后，这部分保护结束。
- 连接页继续展示活动/历史连接；流量页统计默认网卡 direct 出口的累计用量，属于本地估算。

## 本地文件布局

ZIP 便携包在发布 EXE 同级创建下列目录，不自动迁移旧位置的数据。
MSIX 安装目录为只读，数据和下载内核改存到 `%LOCALAPPDATA%\EgressController\data`、
`%LOCALAPPDATA%\EgressController\ruleset`；打包声明提升权限能力，运行仍需管理员授权。
守护服务的安装目录和 ProgramData 状态目录继续独立管理。

```text
EgressController.App.exe
guard-service\EgressController.GuardService.exe
guard-tray\EgressController.GuardTray.exe
data\
  profile.json                 # 用户意图：网卡、端口列表、默认端口、各规则的出口
  ui-state.json                # 页面状态
  usage.db                     # 默认网卡本地流量统计
  current-runtime.json         # 当前运行指针
  last-good-runtime.json       # 可回滚运行指针
  apply.pending.json           # 应用中的崩溃恢复标记
  core\                       # 仅保存 core 指针，不保存 sing-box 二进制
  runtime\config-<sha256>.json
  logs\sing-box.log
  logs\sing-box.log.1
ruleset\
  core\<version>\sing-box.exe
  core\<version>\...
  rules\catalog.json
  rules\<catalog-commit>\<name>.srs
```

`data` 和 `ruleset` 都由程序自动创建，release ZIP 不携带本机配置、连接记录或规则缓存。

服务使用用户 SID 的 SHA-256 前 16 个十六进制字符区分安装，服务名为 `EgressController.Guard.<后缀>`。
守护程序复制到 `%ProgramFiles%\EgressController\Guard\<后缀>`，SQLite 名单/追踪/记录存入
`%ProgramData%\EgressController\Guard\<后缀>\guard.db`。同目录 `registration.json` 保存安装及停用意图，
`desired-policy.json` 保存主程序最新名单（服务手动停止期间也更新）。目录 ACL 限制写入为 SYSTEM/管理员；登记用户只读。
服务异常及管理操作错误分别写入 `service-error.log`、`management-error.log`。

Profile schema 4 读取 schema 1/2/3，保留端口与规则。旧 PRIMARY 迁移为代理角色，旧 eSIM
迁移为直连角色；schema 3 保留默认直连网卡，只有可确定另一角色时才迁移代理网卡。
曾配置超过两张网卡而无法确定角色时要求手动选择；指向第三张网卡的旧规则保留并显示待重新选择，
完成调整前保持进程保护。后续保存清除旧字段；旧版程序不能编辑 schema 4。

## 失败原因与日志目录

主界面顶部始终显示 **打开日志目录** 按钮和可复制的完整目录路径，不需要先启动 TUN。
“网络与内核”保留最近一次 TUN 失败的具体原因，自动重试不会把它替换成只有“正在启动”。
“诊断与日志”显示本次运行最近 200 类失败：首次/最近发生时间、阶段、错误码、重复次数、异常详情，
并提供复制诊断详情和主程序/sing-box 最近日志。顶部最近失败提示属于历史记录，成功恢复后保留；当前运行状态单独显示。

| 日志 | 位置与内容 |
| --- | --- |
| 主程序 | 便携版 `data\logs\controller.log`；MSIX 版 `%LOCALAPPDATA%\EgressController\data\logs\controller.log`。记录准备/下载/校验、启动接管、配置与回滚、联网检测、进程保护、守护通信和界面操作失败。 |
| sing-box | 与主程序日志同目录的 `sing-box.log`，保留内核 stdout/stderr。 |
| 启动或未处理异常 | `%LOCALAPPDATA%\EgressController\logs\startup.log`。主程序初始化失败窗口显示完整原因、日志路径和打开目录按钮。 |
| 守护服务 | `%ProgramData%\EgressController\Guard\<后缀>\logs\guard-service.log`。主程序“独立守护”页与小托盘均有打开目录按钮及完整路径。 |
| 小托盘 | `%LOCALAPPDATA%\EgressController\Guard\<服务名>\logs\guard-tray.log`。小托盘管理窗口顶部提供独立目录入口。 |

每个日志文件约 5 MB，保留一份 `.1` 轮转文件。同一失败在界面累计次数，重复错误最多每 30 秒写一次；
日志记录中的控制 API 凭据会脱敏。磁盘满或没有写入权限时保留界面错误，明确显示日志写入失败，避免日志错误中断保护。
服务启动和提权操作的兼容错误文件仍分别保留在守护数据目录的 `service-error.log` 和 `management-error.log`。

TUN 接管检查允许 Windows 报告的实际网卡本地网段，包括公网 IPv6 `/64` 和公网 IPv4 网段。
必须同时匹配网卡单播地址的前缀和无网关的 on-link 路由；带网关的公网路由、其他 TUN、`/1` 绕行路由、
缺失的 TUN 路由、竞争的默认路由仍会阻止就绪。启动检查最多等待 8 秒，超时显示最后一次具体检查原因。

已有守护服务安装在独立目录，替换主程序发布包不会自动替换服务/小托盘。升级时先退出旧小托盘，
在主程序的“独立守护”页卸载后重新安装服务，再重新打开主程序启动新托盘；已保存的保护名单会保留。
否则旧守护可能继续执行旧版接管检查，且不会产生新增的服务日志。

## NativeAOT 与发布

发布脚本对主程序、守护服务和小托盘分别执行 NativeAOT 发布，再一起打包：

```powershell
./build/Package.ps1 -Version 0.1.5 -SkipMsix
```

产物写入仓库内的 `artifacts\package`：

- `EgressController-win-x64.zip`：主程序及两个独立守护组件的 NativeAOT 自包含 ZIP；
- `SHA256SUMS.txt`：所有发布文件的 SHA-256；
- 不带 `-SkipMsix` 时，若安装 Windows SDK，还会生成未签名 MSIX。

打包脚本还以 `EGRESS_MOCK_ONLY=1` 运行两个守护组件的 `--mock-smoke` 入口，检查原生程序中的
源生成 JSON、SQLite、诊断日志脱敏与假进程保护；入口在 Avalonia、服务、IPC 或系统操作初始化前返回。
主程序管理员入口不会在打包测试中启动。检查 ZIP 中三个 EXE 及依赖完整、不含 `.pdb`。
MSIX 不声明系统服务扩展：仍由主程序显式安装机器服务，卸载 MSIX 前应先在界面卸载守护服务。
CI 的 PR 检查会执行 Release build/test、两个原生 mock smoke 和同一打包脚本；
合并到 `main` 后由 release workflow 生成版本发布包。

## 设计边界

本项目不管理节点、订阅、selector、provider、YAML、Windows 全局代理或应用代理环境变量，
也不向浏览器/WebView 注入代理参数。上游代理应运行在普通本地代理模式，关闭其自身 TUN；
本项目只为经过所管理 TUN 的连接选择出口，无法改写主动绕过该 TUN 的外部套接字。
上游代理负责提供配置的本地 SOCKS5 端口；本项目将
流量交给所选出口，并用 sing-box API 展示实际连接状态。

独立服务缩短主程序未运行时的保护空档，但这是检测后终止进程，不是内核层阻止联网，不能承诺零数据包泄露。
进程可能在被发现并终止前已发出请求；未勾选进程、整个守护服务不可用期间及系统启动早于服务运行的阶段不受此机制保证。
拒绝终止或无法读取身份会明确显示失败，不把“已发送终止请求”当作已经停止。

实现边界说明见
[docs/traffic-migration-boundary.md](docs/traffic-migration-boundary.md)。sing-box 配置字段以
[官方文档](https://sing-box.sagernet.org/) 为准。
