# 本次需求复核

以最近确认的需求为准，早期讨论中已经纠正的方案不再作为实现依据。

| 已确认的规则 | 复核结果与处理 |
| --- | --- |
| “递归/子进程”是目录扫描后保存的 EXE 路径 | ProcessProtection 只按明确路径匹配全部运行实例；ParentPid 不参与范围、分流或重启。旧的后代进程 checkpoint 不恢复为成员。 |
| 换出口不能丢掉已经保存的保护路径 | 发现并修复：重新选择出口原来会覆盖清单。CaptureSelection 现在合并已保存和当前扫描的路径；界面数量/提示同步使用该清单。 |
| 打开应用不该重启 TUN | _routingDirty 的新增来源只有显式扫描清单变化；配置键不包含 PID、进程启动事件或目录元数据。 |
| 独立守护只看主程序与 TUN | GuardHeartbeat 不含联网/DoH/延迟字段；服务核验会话、主程序实例及 TUN。主程序联网检测失败可以关闭应用，但不改变守护红点。 |
| 主程序联网规则独立执行 | 保留 30 秒一轮、失败间隔 5 秒复测、连续三次失败确认；复检保留上次结论。DNS 固定 Cloudflare。 |
| 任意选择两个实际网卡，端口另管 | 保留两个角色、按 GUID 绑定；端口 owner 完整路径优先走 Proxy-代理，多个端口可共用核心。代理 PID 变化但路径不变不改变配置。 |
| 统计显示不控制保护 | HTTP 快照与网速时序没有生命周期调用。缺失数据显示未知、曲线留空，不重启、不重测网络、不终止。 |
| 显示必须真实 | 共用数值纵轴与 60 秒时间轴；UI 刷新不追加样本；使用单调时间；流量条按全部活动连接字节计算占比；延迟来自成功结果字段，不能从错误文字取数。 |
| 未检测就不能说正常 | 修正无代理端口时的就绪文案，不再声称两张网卡均通过联网检测；守护读失败覆盖旧的正常回复，状态未知与手动停止分别显示。 |
| 默认文件日志只写关键原因 | ProtectionLogPolicy 仍过滤普通内核连接输出；保护、生命周期、终止原因独立记录；目录按钮保持明显。 |
| 小托盘完整可控且 AOT | 共享 GuardPanel/GuardianGlyph；保留启动、停止、强停、自启、卸载、记录和日志。打开主程序由托盘宿主处理，预览只发模拟事件。 |

回归验证覆盖固定清单、旧 checkpoint、PID 复用、重新选择出口保留路径、代理防循环、独立心跳与网络检测、统计缺失/恢复/零值/时钟变化、流量占比溢出、守护错误优先级与 UI 状态。全部使用 mock；不触碰真实 TUN、服务、自启或受保护程序。

## Windows 应用与界面迭代

- 识别主 EXE，去掉 VS/IE 诊断/系统工具误入应用列表的问题；Claude SSH 辅助项归入主应用的固定清单。
- 明确的 CLI EXE 是独立选项。元数据查询不执行 CLI，脚本只能在已知专属包中解析原生 EXE；共享解释器不会被加入。
- 兼容旧配置：一致的出口合并、冲突的出口保留并提示统一；旧路径、暂时不可访问的包清单保留；别名查询不扩大旧辅助项的出口范围。
- 路由身份仍是 GUID/完整 EXE 路径。名称、图标、流量归并和筛选只改变展示，不参与 TUN 判定。
- 原生通知图标按其所在显示器定位菜单；主窗口和小托盘都保留可见的退出入口，通知区初始化失败不会把管理窗口藏起来。
- 501 项 mock 测试覆盖现有保护规则以及本次目录归并、CLI、图标失败、路径大小写、网卡名称和多 DPI 菜单几何。真实 TUN/服务/启动项/受保护进程没有用于测试。
