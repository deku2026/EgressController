# 应用升级、启动与稳定列表

## 同一 EXE 为何曾出现两个出口

Store 更新会改变安装目录的版本段。已选 Codex 保存了旧版 EXE，当前版本未命中进程规则：
ChatGPT 域名仍可能命中家宽规则，而 Google/Cloudflare 等目标落到默认 7890。
图标和显示名称相同不代表路径相同。已结束连接保留当时的实际出口，不按新规则改写历史。

## 自动跟随的边界

- 启动扫描、手动刷新列表以及后台每 30 秒读取当前用户的 Windows 包登记。
- 包家族身份包含 publisher，必须完全一致；有多个当前登记时等待下次检查。
- 仅将旧安装根中已保存的相对 EXE 路径映射到当前登记的安装/effective 根，并检查文件存在。
- 保留旧路径、数据目录中的固定清单和用户选择的出口。不同发布者、同名程序、独立 CLI、
  新辅助 EXE、数据目录下新下载的版本均不会被猜测纳入。
- 对实际增加的路径，在配置锁内保存新名单并标记分流待应用，同步主程序与独立守护。
  已有 TUN 监控或启动监督器应用配置；失败时保留新名单并继续保护、重试。
  完全相同的再次检查不触发 TUN 变更。文件日志记录升级原因与具体路径。
- 普通 UI/流量监控没有权限改变清单。没有按 PID 发现路径、没有目录通配分流。

## 启动

非 CLI 且勾选时显示静态启动按钮。配置更新中、TUN/保护未就绪、主入口未确认或不在保存清单
时不可启动；调用边界再次检查。MSIX 使用 AUMID，Win32 使用已确定主 EXE、原参数及工作目录。
目录中的首个 EXE 不能自动成为主程序。缺失入口可在清单弹窗指定主程序，刷新清单后启用。
失败只显示在该应用行；不会改变 TUN、重新扫描清单或终止启动器。CLI 仍由用户在终端启动。

## 列表

保留滚动条。普通刷新复用行对象和已有顺序、新应用追加，保留选择、焦点与视口。分类/搜索
一次发布筛选结果，避免逐项 Move 导致虚拟化面板反复定位。行高固定，启动提示替代路径所在
行，不使列表跳动；完整原因可悬停查看。

## 验证

mock 覆盖同包升级、大小写、不同发布者、目录边界、缺失文件、并发取消/改出口、缓存恢复、
重复检查及真实编译器/守护策略的路径一致性。家宽、第二网卡、代理端口与离线组合验证进程
规则先于域名且离线不回退，代理 owner 规则保持防循环优先级。
隔离 Avalonia 预览验证真实按钮点击、失败显示、CLI 隐藏、500 行筛选虚拟化、刷新焦点与视口。
全部测试不启动真实 TUN、不启动或终止实际应用、不修改服务。
